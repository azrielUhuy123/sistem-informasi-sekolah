# SINERGI-MJ Data Table Cleanup Assessment

**Status:** Read-only cleanup assessment. No files were removed, edited, renamed, or moved.  
**Rule:** “Potentially unused” is not proof of dead code. No deletion is recommended without dynamic-reference and role/page verification.

## 1. Findings at a glance

- Shared table styles are active but globally target Bootstrap `.table` elements, including tables outside ordinary list screens.
- CRUD views define another set of global `.table` and `.table-responsive` rules, with different header, border and hover colors.
- The generic CRUD partial is in use, but not every CRUD feature it renders is wired to the consuming screens.
- The empty table component exists as an empty file and has no discovered call site.
- Manajemen Penugasan has a separate frontend simulation and pagination renderer. It shares pagination class names with the common component, but it is not a duplicate source of the same data or workflow.
- No Vue `<table>` or Vue data-table component was identified in the scanned Vue sources.

## 3. Duplicate / conflict / replacement matrix

| Concern | Evidence | Classification | Safe next step |
|---|---|---|---|
| Global table cell/header styling | `table.css` styles all `.table`; CRUD inline CSS styles `.table` again with `!important` on several properties. | **Confirmed selector conflict** when CRUD page CSS is loaded. | Scope a future design-system class, then migrate consumer-by-consumer. |
| Global minimum widths and mobile font reduction | `table.css` forces 650px/600px minimum table width and reduces mobile header/body text to 11.2px/12.8px. | **Confirmed cross-table constraint; not a duplicate component.** | Replace only after per-table responsive strategy is chosen; do not remove overflow universally. |
| CRUD sort and bulk controls | Table markup, inline scripts and controller capabilities are not consistently connected; sort trigger exists in table partial, scripts are gated by `$routeBulk`, action include is commented. | **Confirmed wiring mismatch / partial feature implementation.** | Treat as a compatibility bug to resolve with owner approval; no “cleanup” deletion or automatic feature enablement now. |
| Empty state component | Empty file and no discovered call site; many pages implement local `@forelse` rows. | **Candidate missing shared implementation, not duplicate code.** | Implement only in a future approved migration; preserve local state text and correct colspans. |
| Pagination rendering | Shared Blade paginator and Manajemen Penugasan JS renderer both use `.table-pagination-*`; one follows Laravel paginator URLs, the other owns local simulation state. | **Shared visual vocabulary, separate behavior.** | Keep behavior separate; share scoped presentation tokens if both are explicitly tested. |
| Search/filter implementations | Server query, Laravel links, DOM filtering and CRUD AJAX search coexist across views. | **Functional diversity, not safe-to-delete duplication.** | Inventory contracts first; do not centralize query logic in a generic front-end component. |

## 4. “Unused” confidence rules

| Evidence class | Meaning | Required action before deletion |
|---|---|---|
| **Confirmed active** | Direct `@include`, `<x-…>`, controller `view(...)`, or imported stylesheet/script was found. | Never delete as cleanup; migrate callers first and preserve compatibility. |
| **Potentially dormant** | No direct static reference found, but dynamic Blade lookup, route-selected view, package behavior or indirect include may exist. | Search dynamic references, view composers, layouts, and role flows; obtain approval. |
| **Confirmed conflict** | Competing selectors are loaded for the same `.table` target. | Scope/reconcile in a migration, not by deleting one stylesheet blindly. |
| **Not established** | Similar names or CSS patterns exist but no same behavior/consumer equivalence was established. | Leave untouched. |

## 5. Cleanup recommendation

1. Keep all current shared table components and module assets in place during the preparation stage.
2. Make a separate approved task to scope `.table` styles and reconcile the CRUD inline override.
3. Before touching `components/crud`, trace its three active call paths: Admin user/year `crud.index`, TU student `crud.table-wrapper`, and any indirect `crud.page` consumers.
4. Treat `crud.page`, `crud.scripts`, `crud.actions`, and `table.empty` as **review candidates only**. None is approved for deletion by this assessment.
5. Keep the Manajemen Penugasan simulation isolated; its pagination shares CSS class names but not server paginator state or business behavior.
6. Exclude PDF/print, timetable matrices and dashboard summaries from blanket cleanup.

No file is marked “safe to delete” on the evidence available in this read-only pass.
