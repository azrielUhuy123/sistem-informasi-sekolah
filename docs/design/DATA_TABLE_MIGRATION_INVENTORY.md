# SINERGI-MJ Data Table Migration Inventory

**Status:** Source-only preparation inventory; no application files were changed.  
**Scan basis:** Blade table markup, associated view markup and styles, route/controller source where directly traceable.  
**Scope count:** 100 literal `<table>` occurrences in 90 Blade files. The count includes repeated tables in dashboards and print/PDF layouts; `components/crud/table.blade.php` is a reusable table partial and renders in more than one page. No `<table>` tag was found in the 12 Vue components included in the prior audit scan.

This is a static inventory, not a runtime route listing. No Laravel, PHP, browser, database, or test command was run. `BVD` means “belum diverifikasi”: the table's exact display route/controller/method was not established from the inspected template and directly linked route/controller evidence. A blank/absent feature means it was not identified in the table view; it does not assert that the backend cannot support it.

## Conventions and shared observations

- **Types:** A Master Data; B Transaction/Workflow; C Academic Data; D Monitoring/Reporting; E Administrative Data; F Other/Specialized. A table can have more than one business characteristic; the listed type is its primary migration class.
- **Readiness:** `P0` = low-risk candidate after approval; `P1` = contract/behavior must be verified before migration; `P2` = specialized or high-complexity presentation; `Blocked` = owner/route decision required. Readiness is a planning assessment, not authorization to implement.
- **Headers:** Names below are literal/static `<th>` labels. `[dynamic]` means a Blade loop or runtime value generates more columns. `No header` means the table has no `<th>` elements. For multi-row tables, the header count is the table's data-column count only when stated; otherwise it is the literal header labels detected.
- **Component:** `card` = `<x-table.card>` wrapper; `actions` = `<x-table.actions>`; `pg` = `<x-table.pagination>`; `links` = Laravel `->links()`; `raw` = direct table markup. `CRUD` is the generic include used by Admin pages.
- **State:** `empty=yes` means a `@forelse`/`@empty` branch exists in the view source. It does not confirm the colspan or visual design is correct. `loading/error=no table state found` means no table-specific loading/error implementation was identified in the server-rendered view.
- **Responsive:** `scroll` means the view wraps the table with `.table-responsive`; `none` means that wrapper was not found. This is not a mobile usability certification.
- **JS:** `yes` means an inline script or relevant inline/listener code was found in the view. `no` means none was detected in that view; shared Bootstrap behavior can still apply.
- **Search/filter/sort/bulk/export:** Values describe the table view or explicitly linked page code. Form inputs are not automatically query parameters; only listed request names confirmed in controller code should be treated as backend query contracts.
- The common CSS baseline is global Bootstrap `.table` styling in [`table.css`](../../resources/css/components/table.css). It sets 650px minimum width (600px at the mobile breakpoint), 12px header text (11.2px on mobile) and 12.8px body text on mobile. `components/crud/page.blade.php` also defines global `.table` overrides.
- Shared table wrappers: [`card.blade.php`](../../resources/views/components/table/card.blade.php), [`actions.blade.php`](../../resources/views/components/table/actions.blade.php), and [`pagination.blade.php`](../../resources/views/components/table/pagination.blade.php). The [`empty.blade.php`](../../resources/views/components/table/empty.blade.php) file is empty and no `<x-table.empty>` usage was found.
- No view found evidence of a shared table loading state or table-request error state. Standard page flash alerts, when present, are not equivalent to a table load-error state.

## I. Migration decision summary

- **100 template table instances** are not 100 equivalent list screens. The inventory includes dashboards, nested-detail tables, matrices, public receipt/status tables and PDF layout tables.
- **62 `x-table.card` call sites across 60 view files** were found in the earlier source scan. The shared wrapper is broadly used but does not standardize the native table body or its behaviors.
- Standard Bootstrap `.table` CSS is global; CRUD also has a competing inline `.table` style block. Most views use horizontal overflow; neither fact proves an accessible mobile experience.
- Pagination is heterogeneous (`x-table.pagination`, Laravel `links()`, and no paginator); use is backend-specific. Some search is DOM-only and therefore limited to the currently rendered rows.
- Prioritize three pilots in [`DATA_TABLE_PILOT_PLAN.md`](./DATA_TABLE_PILOT_PLAN.md). Keep PDF and matrix tables out of a generic CRUD migration.
- Any table marked `BVD` is **not ready for implementation** until its list route, handler, method, and query/payload contract are traced.
