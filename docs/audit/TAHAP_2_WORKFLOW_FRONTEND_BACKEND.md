## 4. Workflow yang hanya terpetakan sebagian

- **AUTH-01:** jalur pencarian login terlihat untuk NIP/NIS, tetapi cabang redirect controller tidak memetakan role `admin` ke dashboard; autentikasi akun aktual tidak diuji.
- **AUTH-06:** endpoint verifikasi memanggil metode verifikasi email yang tidak tampak dideklarasikan pada class `User`/trait yang dibaca. Ketersediaan metode serta hasil request perlu verifikasi terpisah; laporan ini tidak menyimpulkan hasil runtime.
- **AUTH-08:** route profil generik menunjuk `ProfileController::edit`, yang tidak ditemukan pada controller yang diperiksa; form informasi menggunakan PATCH sedangkan route bernama `profile.update` mendaftarkan POST. Halaman/profile flow ini tidak dapat dipastikan sebagai alur yang dapat dipakai.
- **AUTH-09:** terdapat perbedaan opsi role/konfirmasi password antara form pembuatan akun admin dan aturan validasi method `store`; update akun/admin lain tidak ditelusuri lengkap.
- **PUB-01:** alur home dan statistik ditelusuri; isi/aksi semua halaman Vue informasi, prestasi, dan kontak tidak ditelusuri baris demi baris.
- **PPDB-03:** modal pencarian status dapat dipetakan, tetapi GET langsung `/ppdb/status` menampilkan empty-state tanpa formulir pada view yang ditautkan.

## 5. Komponen yang tidak ditemukan atau belum dapat dipastikan

### FAKTA KODE

- Pada `routes/auth.php` yang diperiksa tidak ditemukan route registrasi umum (`register`). Jalur pembuatan akun yang dipetakan pada cakupan ini adalah pembuatan akun Admin dan pembuatan akun siswa pada konfirmasi daftar ulang PPDB.
- Login view menerima `username` dengan label NIP/NIS; `LoginRequest` mencari NIP pegawai atau NIS siswa dan tidak menunjukkan query fallback generik berdasarkan email/username.
- Login response controller memiliki cabang redirect eksplisit untuk `guru`, `tu`, `superadmin`, dan `siswa`; cabang `default` melakukan abort 403. Route dashboard Admin terpisah ada pada `routes/admin.php`.
- Form `admin.users.create` memuat option `murid` dan input `password_confirmation`; validasi pada `Admin\UserController::store` hanya menerima `admin`, `tu`, `guru` dan tidak menyebut aturan `confirmed`.
- Form lookup status pada `layouts.public` mengirim `keyword` dan `tanggal_lahir` ke `ppdb.status.cek`. View status sendiri memperlihatkan data/status/progress jika data tersedia.
- View `resources/views/ppdb/public/daftar.blade.php` mengirim tiga input ke `ppdb.store`; `PublicController::create` yang diperiksa merender view wizard `ppdb.public.ppdb.form`, sedangkan validasi `store` meminta banyak field lain.

### INFERENSI TEKNIS

- Pemanggilan route profile generik (`edit`) dan method HTTP update tidak konsisten dengan deklarasi controller/route pada source yang diperiksa. Efek pada pengguna belum diuji.
- Option `murid` di form Admin tidak termasuk nilai role yang diterima validasi store tersebut. Tidak ada request submit untuk mengonfirmasi respons validasi.
- View `ppdb/public/daftar.blade.php` tidak ditemukan sebagai target `return view` pada controller PPDB yang diperiksa; kemungkinan bukan halaman aktif, tetapi seluruh referensi dinamis/komponen tidak diperiksa.
- Link/login bantuan yang terlihat tidak menghubungkan login view ke route forgot-password pada file yang diperiksa; pengguna dapat mengakses URL reset secara langsung atau melalui jalur lain yang belum diperiksa.

### BELUM DIKETAHUI

- Apakah route/controller yang tidak selaras ditangani oleh perubahan runtime lain, macro, route cache, middleware tambahan, atau kode di luar cakupan pembacaan.
- Apakah database aktif memiliki seluruh tabel/constraint/kolom yang diacu, apakah file berhasil disimpan, dan apakah notifikasi/email dapat dikirim.
- Apakah permintaan browser berhasil, halaman benar-benar ter-render, dan redirect/flash message tampak sesuai.
- Apakah akun/data runtime memiliki kombinasi role, pegawai, siswa, status approval, dan status aktif yang mendukung semua cabang yang ditemukan.
